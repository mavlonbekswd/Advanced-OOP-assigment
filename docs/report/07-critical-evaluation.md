- **Does the application work, and how well does it meet each requirement?** This

  plainly which are met and which are not.
- **What are the limitations?** Known candidates already visible: the checks are not

  levels and no two-player mode, both of which were deliberately deferred.
- **What could be improved?**
- **Is it evident that a plan was made before coding, and was it followed?** The
  preserved planning document and the development log are the evidence here.
- **Were the differences from the initial plan described, with reasons?** Section 4.7
  does this.
- **Were most of the listed object-oriented principles implemented?** Section 4.5
  lists what has been used and what has not; at the time of writing, interfaces,
  inheritance and polymorphism have not yet been demonstrated.

The evaluation must be written after the application is finished, so that it
describes what the code actually does rather than what it was hoped it would do.
